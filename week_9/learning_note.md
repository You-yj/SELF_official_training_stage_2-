# 3.1

## 为什么两个能够得到相同结果的算法，计算效率可能相差很大？

1. 生活类比：从北京到上海，**“结果相同”**（都是到达上海），但你可以选择**步行**，也可以选择**坐高铁**。结果一样，效率天差地别。

2. 计算效率：广义上衡量：**消耗多少资源，得到正确结果**
   - 资源包括：时间效率（运行耗时、指令数量）、空间效率（内存占用）
   - 日常说的计算效率大多指**时间效率**。

3. 在计算机中，导致这种差异的根本原因，可以归结为以下**五个核心层面**：

   - **操作数量的“量级”差异**
     本质上是算法的时间复杂度
   
     例子：在100万个有序数字中查找一个数。
   
     - 算法A（遍历）：从第一个开始逐个找。最坏情况需要查找 **100万次**。
     - 算法B（二分查找）：每次砍掉一半数据。只需要查找 **20次**（因为2^20 ≈ 100万）。
       当数据量变成10亿时，算法A需要10亿次，算法B只需要30次。这种**指数级**的差距，是效率差异的第一推手。
   
   -  **内存访问的“局部性”差异（缓存命中率）**      ##这个缓存命中率好像不是
     现代CPU的速度比内存快几百倍，因此**数据在哪里**比**怎么算**更影响效率。
   
     - 算法A顺序遍历一个二维数组（按行读取），CPU会预先把连续内存加载到极快的L1缓存中，命中率极高。
     - 算法B跳跃式遍历（按列读取），每次访问的内存地址不连续，导致缓存频繁失效，CPU必须反复去慢速的RAM(内存)甚至硬盘取数据。即使两者的算术操作次数完全相同，算法B可能比算法A慢 **10倍甚至100倍**。


## 时间复杂度与程序实际运行时间有什么区别？

1. 时间复杂度
   - 核心定义：时间复杂度描述**算法运行耗时随输入规模 $n$ 增大的增长趋势**/规律，使用**大 O 记号 $O(⋅)$** 表达。
   - 作用：同样算法在不同电脑、不同硬件上运行时间差异巨大，但执行的基本操作次数是固定的，用时间复杂度能排除硬件干扰 。

>  **它不是程序程序运行时间，和 CPU、编程语言无关；只看规模变大之后的长期趋势。**

2. 程序实际运行时间
   - 程序在硬件上跑完真实花费的时长，受 CPU、内存、编译器、编程语言、操作系统共同影响，是可以用计时器测出来的数值。

| 对比维度                | 时间复杂度 O(f(n))                                      | 程序实际运行时间                                         |
| ----------------------- | ------------------------------------------------------- | -------------------------------------------------------- |
| **本质含义**            | 描述**运算量随输入规模 n 的增长趋势**                   | 程序在机器上执行真实消耗的物理时长                       |
| **计量单位**            | 无单位（渐近阶符号）                                    | 秒、毫秒、微秒等时间单位                                 |
| **是否依赖软硬件**      | 与 CPU、内存、编程语言、编译器**无关**                  | **高度依赖**硬件、操作系统、语言、编译优化               |
| **表达式特点**          | 忽略常数系数、低阶项，只保留最高阶项$T(n)=100n+50⇒O(n)$ | 包含全部开销：常数、循环内操作、访存、函数调用等完整耗时 |
| **作用**                | 预判：数据规模很大时算法是否会超时，用于算法选型        | 衡量真实性能，用来调优、基准测试                         |
| **能否相互推导**        | 不能精确算出运行时间；仅能定性预判趋势                  | 不能反推出时间复杂度，实测结果受大量干扰因素             |
| **同复杂度下表现**      | 复杂度标记完全相同                                      | 运行时间可能相差数倍、上百倍（常数、缓存影响）           |
| **小规模数据规律**      | 结论只在**n 足够大**时成立                              | 小规模场景可能出现「复杂度高的算法跑得更快」             |
| **是否考虑内存 / 缓存** | 不考虑，仅统计基础运算次数                              | 受缓存命中率、内存带宽、分支预测显著影响                 |

# 3.2～3.3

## 为什么计算机通常不能精确表示 0.1 ？

- 核心：
  因为计算机（基于二进制）的“十进制小数”表示法，就像人类（基于十进制）无法用**有限位数**精确写出 **1/3** 一样——**0.1 在二进制中是一个“无限循环小数”，而计算机的内存（寄存器）是有限的，存不下无限的数字，只能被迫截断，所以永远是个近似值。**

- 十进制小数和二进制小数的原理完全一样，只是基数不同：

  - **十进制**：小数点后第1位是 $10^{−1}$（十分位），第2位是 $10^{−2}$（百分位）……

  - **二进制**：小数点后第1位是 $2^{−1}$（二分之一），第2位是 $2^{−2}$（四分之一）……
    - $0.5=2^{−1}$ 的二进制为 $0.1$
    - $0.25=2^{−2}$ 的二进制为 $0.01$
    - $0.75$ 的二进制为 $0.11$

- 类比

  - 十进制表示 $1/3$ ：$0.333333……$

    ```python
    print(1/3)
    ```

    ```
    0.3333333333333333
    ```

  - 二进制表示 $1/10$ ：

    - 规则：小数部分不断乘以 $2$，取出整数部分，剩余小数继续运算；把取出的整数依次写在小数点后

    - $$
      \begin{align*}
      0.1 \times 2 &= 0.2 \quad\text{取出整数：}\boldsymbol{0}\\
      0.2 \times 2 &= 0.4 \quad\text{取出整数：}\boldsymbol{0}\\
      0.4 \times 2 &= 0.8 \quad\text{取出整数：}\boldsymbol{0}\\
      0.8 \times 2 &= 1.6 \quad\text{取出整数：}\boldsymbol{1}\\
      0.6 \times 2 &= 1.2 \quad\text{取出整数：}\boldsymbol{1}\\
      0.2 \times 2 &= 0.4 \quad\text{取出整数：}\boldsymbol{0}\quad\text{（开始循环）}
      \end{align*}
      $$
      
    - 故 $1/10$ 的二进制为：$0.00011001100110011……$
    
    ```python
    import struct
    def float_to_binary_64(num):
        """输出 float 在内存中的 64 位二进制"""
        # 将浮点数打包成 8 字节（双精度），再解包为无符号长整型
        packed = struct.pack('!d', num)   # '!d' 表示网络字节序的双精度
        unpacked = struct.unpack('!Q', packed)[0]  # '!Q' 表示无符号长整型
        # 转为二进制字符串，去掉 '0b'，并补足 64 位（前面补0）
        return bin(unpacked)[2:].zfill(64)
    
    # 测试 0.75（理论精确，内存表示也精确）
    print(float_to_binary_64(0.75))
    # 测试 0.1（你会发现尾数是无限循环 0011 的截断）
    print(float_to_binary_64(0.1))
    ```
    
    ```
    0011111111101000000000000000000000000000000000000000000000000000
    0011111110111001100110011001100110011001100110011001100110011010
    ```
    
    就像十进制的 0.750.75 可以写成科学计数法 $1.5×10^{−1}$一样，**计算机把所有小数**（除了0）都强行统一成这种格式：
    
    以 $0011111110111001100110011001100110011001100110011001100110011010$ 为例
    
    ```
    0 | 01111111011 | 1001100110011001100110011001100110011001100110011010
    ```
    
    1. 第1部分：符号位（0）—— 正负号
    
       - 占 **1 位**；
       - **0** 代表正数，**1** 代表负数；
       - 我这里是 `0`，所以这是一个正数。
    
    2. 第2部分：指数位（01111111011）—— 决定数量级
    
       - 占 **11 位**
       - 这里存的是**“偏移后的指数”**。双精度的偏移量（偏置值）是 **1023**
       - 换算成十进制是 **1019**，减去偏移量 1023，真实指数 = $1019−1023=−4$
       - 这意味着最终结果要乘以 $2^{−4}$。
    
    3. 第3部分：尾数位（1000...）—— 决定具体数值
    
       - 开头的“隐含 1”补上，实际有效数字是
         **1.1001100110011001100110011001100110011001100110011010**（二进制）
    
    4. 还原
    
       由于指数位为 $2^{−4}$ ，故要把尾数位小数点左移 4 位得到： $0.00011001100110011001100110011001100110011001100110011010$
       
    5. 为什么后面是1010（“四舍五入”）
    
       算机的尾数只有 52 位，存到第 52 位时，发现**第 53 位是 1**（即后面还有尾巴）。根据 IEEE 754 的**“向偶数舍入”**规则，计算机**进位**了，导致最后的 `...1001` 变成了 `...1010`。
    
    6. 到底对于多少？
    
       如果你把这串二进制还原成十进制，它**不是数学上的 0.1**，而是： $0.1000000000000000055511151231257827021181583404541015625$
    
  
## 为什么计算机 0.1+0.2=0.30000000000000004 ？  

0.1 实际存的是：0.1000000000000000055511151231257827021181583404541015625

0.2 实际存的是：0.200000000000000011102230246251565404236316680908203125

硬件相加（纯粹二进制运算）：CPU 将这两个二进制近似数直接相加，得到一个“中间结果”：0.3000000000000000166533453693773481063544750213623046875

IEEE 754 规定，当结果正好卡在两个相邻的可表示浮点数**正中间**时，要把尾数末位舍入成 **偶数**（0）。
此时，这个中间结果恰好**非常非常接近**但不完全等于下一个可表示的二进制数。经过舍入后，内存里最终存的是这个数：0.3000000000000000444089209850062616169452667236328125

当你用 Python 的 `print` 输出时，编译器为了美观会把它精简到 17 位有效数字，于是你看到了：
**`0.30000000000000004`**

## 为什么浮点数运算不一定满足数学中的结合律？

实数加法满足 $(a+b)+c=a+(b+c)$

但**二进制浮点数（IEEE 754）不保证成立**，

根本原因：**浮点数精度有限，相加时会发生舍入误差；不同运算顺序，舍入时机不同，最终结果不一样。**

# 3.4~3.5

## 什么是舍入误差和截断误差？

- 舍入误差：指由于计算机无法用无限的精度来表示所有实数而产生的误差。

  当一个数的真实值所含的有效数字超出了计算机所能表示的范围时，就必须进行舍入（或截断）。这个过程引入的误差便是舍入误差。这种误差是计算机硬件和算术单元的直接产物。

- 截断误差：指用有限的计算步骤去逼近一个无限过程时产生的误差。

  在实际计算中，我们必须将这些过程“截断”为有限的步骤。例如，使用泰勒级数的前几项来近似一个函数，或者用有限的差分来近似导数，都会引入截断误差。这种误差是算法本身的数学属性，与计算机的硬件实现无关

## 什么是前向误差和后向误差？两者分别回答什么问题？

- 前向误差：
  - 对于一个计算任务，其真实解为 $y$，计算解为 $\hat y$，**绝对前向误差定义为 $Δy=|\hat y−y|$**，**相对前向误差定义为$\frac{\left| \Delta y \right|}{\left| y \right|} = \frac{\left| \hat{y} - y \right|}{\left| y \right|} \quad (y \neq 0)$**
  - 前向误差回答了这样一个问题：“我们的答案偏离了多远？” 它是在问题的“输出空间”中度量的。

- 后向误差：
  - 给定一个计算结果 $\hat y$ ，后向误差是对原始输入 $x$ 的一个扰动 $δx$ ，使得$f(x + \delta x) = \hat{y}$ 。通常关心的是满足此条件的“最小”扰动。**绝对后向误差**是 $∣δx∣$，而**相对后向误差**是 $\frac{∣δx∣}{∣x∣}$ (假设 $x≠0$)。
  
    - 以解方程 $Ax=b$ 为例：输入为 $A$、$b$，输出位数值解 $x_{num}$
      **后向误差（量）** 定义为 $\eta = \min_{\Delta A, \Delta b} \left\{ \max\{\|\Delta A\|, \|\Delta b\|\} \;\middle|\; (A+\Delta A)x_{\text{num}} = b + \Delta b \right\}$
  
      **这意味着**：我们不问这个算法得到的“解差了多少”，我们只问“矩阵 $A$ 和右端项 $b$ 被改动了多少”，只知道这个算法得到的解 $x_{\text{num}}$ 肯定在满足我们想要的误差下，是其邻近问题 $(A+\Delta A)x = b + \Delta b$ 数值解。
  
      若 $\Delta A$，$\Delta b$ 非常小，及后向误差非常小，及这两个邻近问题非常接近，那么称这个算法是**后向稳定的**。
  
  - 回答了这样一个问题：“我们解决的究竟是哪个问题？” 它是在问题的“输入空间”中度量的。
  
- 广义上，前向误差，后向误差以及条件数都是围绕着一个核心问题：我们如何出色地求解我们**写下的数学模型**

# 3.6~3.7

## 什么是问题的病态性？

先区分：病态、良态；适定 / 非适定

| 对比维度          | **适定 / 非适定 (Well-posed / Ill-posed)**                   | **良态 / 病态 (Well-conditioned / Ill-conditioned)**         |
| ----------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **1. 关注对象**   | 数学问题本身的**“结构逻辑”**                                 | 数学问题对数据的**“敏感体质”**                               |
| **2. 判定标准**   | **Hadamard 三条件**： <br />① 解存在 ② 解唯一 ③ 解连续依赖于输入 | **条件数 (Condition Number)** 的大小： <br />条件数 ≈ 1 → **非病态**；条件数 >> 1 → **病态** |
| **3. 本质属性**   | **定性 (Qualitative)** —— 非黑即白。 <br />要么满足（良态），要么不满足（非良态）。 | **定量 (Quantitative)** —— 渐变刻度。 <br />病态程度是连续的（条件数 10、10⁶、10¹⁰…）。 |
| **4. 问题根源**   | **建模层**。 数学模型本身“没建好”（比如方程个数少于未知数）。 | **几何/物理层**。 数据之间有极强的“近似线性相关”（比如两条直线几乎平行）。 |
| **5. 能否修复？** | **必须改模型**。 例如：添加正则化项、增加约束条件，把“非良态”变成“良态”。 | **只能缓解，无法根除**。 可用预处理 (Preconditioning) 降低条件数，但无法改变该问题天生敏感的事实。 |
| **6. 典型例子**   | **非良态**：求解 $x^2=−1$（实数范围无解）。 <br /> **良态**：求解 $x^2=2$（有唯一正解）。 | **病态**：希尔伯特矩阵线性方程组（条件数极大）。 <br />**非病态**：单位矩阵线性方程组（条件数 = 1）。 |

即使一个问题是适定的，如果它处于“病态”条件下，其解也可能对数据中的微小噪声极为敏感。

**问题的病态性**：问题的**解**对**输入数据**的微小扰动高度敏感，即输入数据发生极微小的变化，都会导致输出解发生极其剧烈的变化。

## 问题的条件性与算法的稳定性有什么区别？

- **条件**是问题固有的数学属性，独立于求解它的任何特定算法。一个病态问题无论用多好的算法求解，其解对输入的微小扰动都非常敏感。

- **稳定性**是算法的属性。一个**稳定算法 (stable algorithm)** 对于给定的输入，其计算结果与真实解的差异不大。更精确地说，一个稳定算法得到的解，是某个略微扰动过的输入所对应的精确解。

###### 3.6 条件、条件数与良态性

**条件**(问题的这种内在敏感性，我们称之为**条件 **)
**条件数**(衡量问题敏感性的标尺)
**绝对条件数**：对于一个可微函数 $f(x)$，根据泰勒展开，当扰动 $Δx$ 很小时，输出的变化 $Δy=f(x+Δx)−f(x)≈f′(x)Δx$ 。这就是说，输出的绝对变化大约是输入绝对变化的 $∣f′(x)∣$ 倍。因此，**$∣f′(x)∣$** 就是问题的绝对条件数。
**相对条件数**： $\kappa_{\text{rel}}(x) = \left| \frac{x f'(x)}{f(x)} \right|$
**应对病态或不适定问题**：1. 预处理(对于病态、条件数大的良态问题，可将其转化为一个**等价**但**条件数更小**的问题；)；2. 正则化(对于非适定问题，需要从根本上修改问题，正则化通过向原问题添加一个惩罚项来引入额外信息，从而将非良态问题转化为一个邻近的良态问题)
